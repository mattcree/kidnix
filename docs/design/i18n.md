# Internationalisation

> How kidnix speaks a language that is not English, what it costs to add one,
> and what is deliberately not translated.
>
> Decision record: `docs/adr/0012-internationalisation.md`.
> Evidence: `docs/research/06 §4.7` (who needs this), `§4.1` (fonts),
> `docs/spikes/tts.md` (the voice).

## 0. Why

A quarter of the children this OS is for do not speak English at home.

| | |
|---|---|
| Pupils in English primary schools with a first language other than English | **23.8%** (DfE, Jan 2026 census) — 30.6% in nurseries |
| Largest non-English main language, England & Wales | **Polish, 612,000** (Census 2021), then Romanian, Panjabi, Urdu |
| Welsh speakers aged 3+ in Wales | **538,300 (17.8%)** — the lowest ever recorded |
| Welsh among **5–15 year olds** | **down 6.0 percentage points** 2011→2021 |

The last row is kidnix's exact age group, and it is the one place where this
project could plausibly *help* rather than merely cope. Research 06 also makes
a subtler point worth keeping: a **bilingual** arrangement (English UI, home
language read aloud) may serve more EAL families than a full locale switch,
because parents' and children's language needs differ. That is why the
language is a property of the **child's profile** and not of the machine.

## 1. The mechanism, in one page

Plain GNU gettext, domain `kidnix`, and the **msgids are the en_GB strings**.
There is no en_GB catalogue and there must never be one: with nothing
installed, `gettext` returns the msgid, which is the sentence, unchanged. A
machine with no `.mo` anywhere behaves byte-identically to the shell before any
of this existed — asserted in `tests/test_i18n.py` and again inside the image
in `tests/image/test_shell.sh`.

`kidnix_shell/i18n.py` exports four things:

| | when it translates | where you use it |
|---|---|---|
| `_("...")` | **now** | inside a function or method |
| `N_("...")` | never — marks for extraction | a module-level constant |
| `NP_(sing, plur)` | never — marks a **plural pair** | a module-level constant |
| `ngettext(sing, plur, n)` | **now**, by the catalogue's plural rule | anywhere a noun is counted |

**The one rule: never `_()` at module level.** A module-level `_()` is
evaluated when Python first imports the file, which is before anybody knows
which child is sitting down; it would freeze the language of whichever process
imported first. So a constant holds the *msgid* and the use site translates:

```python
RESTING_TITLE = N_("Resting")          # module level: the msgid

def rest_title(*, bedtime: bool) -> str:
    return _(SLEEPING_TITLE) if bedtime else _(RESTING_TITLE)
```

This is the deferred-translation idiom from the Python `gettext` docs, and it
is why every existing constant kept its name, its value and its tests.

`kidnix_activity/i18n.py` re-exports all of it. An activity shares the shell's
domain and catalogue — they are one release (`build_files/60-shell.sh`), and a
child cannot tell which process drew a sentence.

### Where the catalogues live

```
/usr/share/locale/<lang>/LC_MESSAGES/kidnix.mo     the image
shell/po/<lang>/LC_MESSAGES/kidnix.mo              a dev checkout
```

Both are searched, image first. The `.mo` files are **not** in git: they are
compiled from `shell/po/*.po` by `just po-compile` (dev) and by
`build_files/60-shell.sh` (image). A repo carrying both would have two sources
of truth and no way to notice when they disagreed.

### Where the language comes from

First non-empty wins:

1. the active **profile's** `language` — `[[profiles]] language = "cy"`;
2. `[access] language` in `parent.toml` — the machine's answer;
3. the environment: `LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, `LANG`;
4. `en_GB`.

A language with no catalogue is **not an error**. It falls back to the msgids,
which is en_GB, which is a computer that works; one INFO line says why.

### What a profile switch does

Text already on screen does not change by itself — a GTK label is a string that
was built once. So when, **and only when**, the incoming profile's language
differs from the one in force (`ShellWindow._use_language`):

1. the catalogue is reinstalled;
2. speech-dispatcher is sent `SET SELF LANGUAGE` immediately, so the next
   utterance is in the new language;
3. the surfaces are rebuilt on the next main-loop turn, via the same
   `_build_content()` a monitor change uses. It is deferred with `idle_add`
   because the switch happens inside the profile button's own activation, and
   tearing down the widget that is mid-signal is how a shell crashes in front
   of a child.

A same-language switch — every switch on a monolingual machine — does nothing
at all. That is deliberate: it is what keeps the en_GB path exactly the code it
was.

## 2. Grammar you cannot get away with in English

### 2.1 Plurals

Welsh has **six** plural forms. Polish has three. English has two, which is why
`if count == 1` looked like a language feature rather than an accident.

```
cy: nplurals=6; plural=(n==0 ? 0 : n==1 ? 1 : n==2 ? 2 : n==3 ? 3 : n==6 ? 4 : 5);
pl: nplurals=3; plural=(n==1 ? 0 : n%10>=2 && n%10<=4 && (n%100<10 || n%100>=20) ? 1 : 2);
```

Every counted noun in the shell goes through `ngettext`, which asks the
catalogue's own `Plural-Forms` header. The result, from the sample catalogues:

| count | en_GB | cy | pl |
|---|---|---|---|
| 1 | one thing | un peth | jeden rzecz |
| 2 | two things | dau **b**eth | dwa rzeczy |
| 3 | three things | tri **ph**eth | trzy rzeczy |
| 5 | five things | pump peth | pięć rzeczy |

Welsh mutates the noun after a numeral. No amount of "singular or plural" can
express that, and no amount of English intuition would have predicted it.

`NP_()` exists for one mechanical reason: `xgettext` emits a `msgid_plural`
entry only when it can see both strings **in the call**, and a constant
declared at module level is not in any call. `NP_("{count} thing",
"{count} things")` is a call it can see, and it returns the pair unchanged for
the use site to hand to `ngettext`.

### 2.2 Word order

Every composed sentence uses **named** placeholders, never concatenation and
never positional `%s`:

```python
MADE_SENTENCE = N_("You {verb} {count} {noun}")
```

A translator may reorder them, drop one, or fold the verb into the noun. The
Polish sample does exactly that (`"{verb} {count} {noun}"` — no subject
pronoun, because Polish does not need one).

### 2.3 Known limitation: number-word agreement

`"{count} thing"` puts a **word** in `{count}`, not a digit, because the child
never sees a digit (01 #19). In Polish "one" inflects with its noun — *jedna
rzecz*, not *jeden rzecz* — and a translator can only fix that by folding the
number into each plural form (`msgstr[0] "jedna rzecz"`, ignoring `{count}`).
That works, and it is not obvious. It needs a native speaker's judgement rather
than a mechanism; recorded here so the first translator is not surprised.

## 3. The voice

`kidnix_shell.speech` sends the shell's own language to speech-dispatcher —
SSIP `SET SELF LANGUAGE` via `python3-speechd`'s `set_language`, and `-l` on
the `spd-say` fallback. Live: a profile switch changes the voice on the open
connection.

**A Welsh Home screen read aloud in an English voice is worse than either
alone.** A child learning to match a shape to a word hears the letters
mispronounced, which is the opposite of what read-aloud is for.

The image bundles exactly one Piper voice family, `en_GB-cori`
(`docs/spikes/tts.md`), ≈178 MB of voices for one language. Anything else falls
through to **espeak-ng**, which speaks around a hundred languages
intelligibly and none of them beautifully — the same degradation ADR-0008
already accepts as the fallback path.

Adding a good voice for a language means adding a Piper `.onnx` + `.json` pair
to `/usr/lib/kidnix/piper/voices/` and a speech-dispatcher module entry, in
`build_files/65-tts.sh`. Costs, from the measurements in `docs/spikes/tts.md
§2.1`: **63 MB (medium) or 114 MB (high) per voice on disk**, 114–160 MB
resident while speaking.

Candidate voices, in the order research 06 §4.7 ranks the languages:

| language | speech-dispatcher tag | Piper voice (needs verifying against the archive) |
|---|---|---|
| English (UK) | `en-GB` | **`en_GB-cori-high`**, shipped |
| Welsh | `cy` | `cy_GB-gwryw-medium` |
| Polish | `pl` | `pl_PL-gosia-medium`, `pl_PL-darkman-medium` |
| Romanian | `ro` | `ro_RO-mihai-medium` |
| Panjabi | `pa` | none known — espeak-ng |
| Urdu | `ur` | none known — espeak-ng |

> **Not verified.** The child session has no network egress and this machine
> did not download the archive. The `en_GB-cori` row is measured
> (`docs/spikes/tts.md`); the rest are from memory of `rhasspy/piper-voices`
> and **must be checked before anyone plans around them**. The espeak-ng
> fallback needs no verification: it is already in the image and already the
> ADR-0008 fallback.

Captions need nothing. A caption is the text that was spoken, and it was
translated before it reached the caption strip.

## 4. Activity manifests

A manifest is **content**, not code: its `name` and `audio_label` come from a
package we did not write, so they do not belong in our catalogue. Manifests
carry their own translations as suffixed keys:

```toml
name         = "Letters & numbers"
name_cy      = "Llythrennau a rhifau"
audio_label  = "Letters, counting and shapes. Choose a game."
audio_label_cy = "Llythrennau, cyfrif a siapiau. Dewiswch gêm."
```

Localisable fields: `name`, `audio_label`, `goal`, `shelf_group_name`,
`shelf_group_audio_label`. Resolution is most-specific-first —
`name_pl_PL`, then `name_pl`, then bare `name` — in
`kidnix_shell.activities.localised`. A manifest with no translations is exactly
the manifest it was, and an unknown `name_xx` is a known field for a language
we have not been told about, not a typo.

## 5. How to add a language

Say `pl`. Nothing below is a code change.

**1. Strings.**

```
cd shell
just po-extract                       # refresh po/kidnix.pot
msginit --locale=pl --input=po/kidnix.pot --output=po/pl.po
$EDITOR po/pl.po                      # or hand it to a translator
just po-compile                       # -> po/pl/LC_MESSAGES/kidnix.mo
just po-check                         # msgfmt --check; part of `just ci`
```

Check the `Plural-Forms:` header is right for the language before anything
else; `msginit` fills it in from gettext's own table and it is the one line
that cannot be fixed later by re-translating.

When the source moves, `just po-update` merges the new `.pot` into every `.po`
and marks the changed entries fuzzy.

**2. Turn it on.** Per child, in `/etc/kidnix/parent.toml`:

```toml
[[profiles]]
id = "zosia"
name = "Zosia"
language = "pl"
```

or for the whole machine, `[access] language = "pl"`.

**3. The voice.** §3. Nothing to do to *degrade* gracefully — espeak-ng is
already there — but check what it sounds like before deciding it is enough.

**4. Fonts.** Checked against the real image (`localhost/kidnix`, `fc-match`
with an explicit charset), and **Andika covers more than research 06 §4.1
claims**:

| script | `fc-match "Andika:charset=…"` |
|---|---|
| Welsh (ŵ Ŵ ŷ Ŷ) | **Andika** |
| Polish (ą ć ę ł ń ś ź ż) | **Andika** |
| Romanian (ă â î ș ț) | **Andika** |
| Cyrillic (а б в … Ж) | **Andika** |
| Gurmukhi (ਪੰਜਾਬੀ) | Noto Sans Gurmukhi |
| Arabic / Urdu (اردو) | Vazirmatn |

Andika's own coverage is Latin through U+0320 plus Cyrillic U+0400–U+052F, so
every Latin-script and Cyrillic-script language kidnix is likely to want keeps
the **single-storey a and g a five-year-old sees in a phonics book** — which is
the whole reason Andika was chosen (`build_files/36-fonts.sh`). Gurmukhi and
Arabic fall back to a different face, and losing the literacy letterforms is a
real cost for a beginning reader, not a cosmetic one. Record it if it happens.

**5. Sample catalogues.** `po/cy.po` and `po/pl.po` are **pipeline samples, not
reviewed translations**, and say so in their own headers. They carry ~20
well-known words each and correct plural rules, and exist to prove three
things: that the round trip works, that six and three plural forms both
survive it, and that a half-translated catalogue degrades to en_GB **per
string** rather than per file. Before either ships to a family it needs a
native speaker — ideally one who teaches five-year-olds.

## 6. What is not localised, and why

**Activity corpora.** *Sounds & Words* is English phonics. A Welsh child does
not need it translated; they need Welsh phonics, which is a different sequence,
a different set of graphemes and a different pedagogy — a different activity,
not a string table. The same is true of KLettres' letter sounds and of
GCompris' reading exercises, both of which already ship their own per-language
content. Translating the *tile* while the *activity* stays English would be the
worst of both: a child invited in their own language into something they cannot
do.

**Manifest ids, config keys, CSS classes, icon names, log lines.** Machine
vocabulary. A parent reading `/etc/kidnix/parent.toml` reads its comments,
which are English; that is a documentation job, not a gettext one.

**The starter PIN command.** `sudo kidnix-set-pin` appears verbatim inside
translated sentences. A command is never translated.

**Right-to-left layout.** Out of scope for v0.1. Urdu and Arabic need mirrored
layout (the band, the pager arrows, the sun's horizon), Nastaliq shaping, and a
font Andika does not cover. Half-mirroring Home would be worse than not
offering it. Recording that we know is the honest position; the string
plumbing here does not prevent it later.

**Numbers as digits.** Unchanged: the child still never sees one. The grown-up
sheet does (`Used 12 of 60 minutes today`), and that is an adult surface.

## 7. The guard

`tests/test_i18n.py::test_no_child_facing_string_escapes_gettext` walks the AST
of every file a child's words come from — `band.py`, `ritual.py`, `resting.py`,
`feedback.py`, `suggestions.py`, `next_after.py`, `sun.py`, `words.py` and
every `screens/*.py` — and fails on a string literal that is not inside
`_()`, `N_()`, `NP_()` or `ngettext()`.

Exempt, by shape rather than by list: docstrings, log calls, lowercase slugs
(CSS classes, icon names, ids), CSS selectors, hex colours, private attribute
names, command-line flags, absolute paths, printf specs. Four literals are
exempt **by name**, each with its reason on the line above it in `ALLOWED`.

The guard is the point. Six months from now somebody adds a sentence to Home in
a hurry; this is what tells them, in CI, instead of a Welsh family finding out.

## 8. Activities

§4 is about a manifest, which is content. This section is about the **code** —
the four first-party activities and the SDK they are built on. The
checkpoint-2 audit found zero `_()` calls in any of them three commits after
the shell was localised; the plumbing was there and nobody had used it.

### 8.1 One catalogue, four programs

An activity is a separate *program* and not a separate *release*
(`build_files/60-shell.sh` installs the shell, the SDK and every activity
together), so it shares the shell's `kidnix` domain rather than shipping one of
its own. Two catalogues would be two places for the same word to be translated
differently, and a child cannot tell which process drew a sentence. It is why
`shell/po/kidnix.pot` is the only `.pot` in the repository and why
`just po-extract` scans `../activities` as well as `kidnix_shell` — skipping
`tests/` and any `.venv`, because a developer's virtualenv is thousands of
third-party files and a stray `_("...")` in one of them is not our sentence.

### 8.2 `<package>/i18n.py`, and why it is not one line

Every activity has one, and every one of them is the same two-branch wrapper:
the SDK's `_`/`N_`/`ngettext` when `kidnix_activity` is importable, plain
identity functions when it is not. **The pure half of an activity must import
with no SDK at all** — `just test-headless` is each package's CI floor and runs
`words.py`, `items.py`, `routine.py` on a machine that may have neither
`kidnix_activity` on its path nor `gi` anywhere. A hard
`from kidnix_activity.i18n import _` in a corpus module would make the words
half depend on the window half, which is the split
`docs/design/activity-sdk.md` §2 asks for. `xgettext` reads source, not
imports, so extraction never cares which branch a machine took.

`NP_` is defined *in* that wrapper rather than imported, so it exists on both
branches; `--keyword=NP_:1,2` is already in `shell/Justfile`.

### 8.3 The SDK's own three sentences

`kidnix_activity/widgets.py` holds the words every activity inherits without
writing them: the replay button's *"Say it again."*, the grown-up card's
*"Your turn, grown-up"* and its *Done*. A literal there is a literal in four
activities at once. `GrownUpTurn(title=…, done_label=…)` therefore default to
**`None`**, not to the msgid: the SDK's own words are translated inside
`__init__`, when a child is already sitting down, and an activity's own
sentence — already translated, from its own catalogue entry — passes through
untouched rather than being looked up twice.

### 8.4 Words a language does not build the way English does

The three activities added here each hit the same wall in a different place,
and all three answers are the same shape: **a table of msgids, plus one msgid
per sentence *shape*, with named placeholders**.

| | the table | the shapes |
|---|---|---|
| Numbers | `NUMBER_WORDS` — "zero" … "ten" | `"{shown} and {missing} make {total}."`, `"Yes, {number}."`, `"Here are {shown}. How many more make {total}?"` |
| Clock | `HOUR_NAMES`, `_PAST`, `_TO` | `"{hour} o'clock"`, `"{past} {hour}"`, `"{to} {hour}"`, `"about {time}"` |
| Letters | the three crayons | `"Your letter for {name}."`, `"Posted! A grown-up will send it to {name}."`, `"A letter from {name}."` |

The clock is the one worth reading twice. `f"{minute} {hour}"` is not telling
the time in any language but this one — German's *halb vier* is half past
**three** while naming four — so `ClockTime.words()` composes through
`ON_THE_HOUR` / `PAST_THE_HOUR` / `TO_THE_HOUR`, which are three *separate*
msgids precisely so a translator can reorder "past" without touching "to".
The numbers' `NUMBER_WORDS` deliberately share msgids with the shell's own
`kidnix_shell/words.py` table: "three" is one entry in the catalogue and one
decision for a translator.

**A name is never translated.** A recipient in Letters, a routine moment a
grown-up typed into `clock_time.toml` — both go through `_()` and come back
unchanged, because they are in no catalogue; our own eight default routine
names *are* msgids and do change. `RoutineItem.name_words` is where both meet,
and the routine strip measures the **translated** name, because a strip
measured in English and drawn in Welsh is a strip that overflows the panel.

### 8.5 The guards

One `tests/test_i18n.py` per package, plus `shell/tests/test_activity_sdk_i18n.py`
for the SDK. Each is an AST walk, not a grep, and each asserts the same three
things: no `_()` at module level; no child-facing widget handed a bare string
literal; and `xgettext` — run with the same keyword list `just po-extract`
uses — can actually see every msgid. Each also carries a test that the guard
*would* fail on the line the audit found, because a guard nobody has seen fail
is a guard nobody has tested.

What stays a literal, in every package: manifest ids, CSS classes, icon names,
Journal `kind` slugs, log lines — and, in Letters, `STATUS_WAITING` and
`STATUS_UNPOSTED`, which are written **into `letter.json` and the outbox
manifest**. A stored status that changed language with the child's profile
would be a file that means two different things on two machines, and the folder
a grown-up posts from is the last place for that.
